Self-hosting guide

Run the portal on a college server or any computer with Docker. Your data never leaves your machine.

Requirements

  • A server or VM with Docker Engine 24+ and the Compose plugin (Docker Desktop also works), about 1 GB RAM and 2 GB disk.
  • For real elections: a DNS name with HTTPS in front of the portal.
  • For booths: Ubuntu 22.04+ computers on the same network, and an authenticator app (Google Authenticator, Aegis, Microsoft Authenticator) for the Election Officer.

1. Install

  1. Get the code 
    git clone https://github.com/s0n4jit/e-voting.git
cd e-voting
cp .env.example .env
  2. Fill in .env

    Set POSTGRES_PASSWORD (letters and digits only), and two different long random values for SECRET_KEY and JWT_SECRET_KEY:

    python -c "import secrets; print(secrets.token_hex(32))"

    The backend refuses to start in production with the development defaults. Never commit .env.

  3. Start 
    docker compose up -d --build
docker compose ps
  4. Run the wizard

    Open http://<server>/. Enter your institution, logo, slip ID letters (default SUE), the Election Officer account and the first election, then press Install and set up two-step verification. Your logo becomes the site's favicon; without one, the default logo is used.

If the server is reachable before you finish the wizard, set SETUP_TOKEN in .env so only you can run it.

2. HTTPS and reverse proxy

Serve the portal over HTTPS only. With Caddy (automatic certificates), set WEB_PORT=8080 and PROXY_HOPS=2 in .env, then:

vote.example.edu {
    reverse_proxy localhost:8080
}

An nginx example and the Render/Supabase/Vercel option are in Installation guide and Deployment guide.

3. Prepare the election

  1. Programmes: add them or import a CSV (level,programme,department,terms).
  2. Candidates: each with a photo and department.
  3. Desk Officers: one account per desk.
  4. Move the election: Registration → Ready → Voting active → Voting closed → Results published.

4. Set up voting booths

Download the official desktop booth app (Windows .exe, Ubuntu .deb, or Linux .AppImage) on each booth machine from the officer panel. Launch the app, enter your portal address and printer, and click Save and start voting. Generate a booth token in the officer panel to activate the booth. The app runs in locked full-screen mode and accepts only votes and numpad entries.

5. Operate

TaskCommand
Status of the installationdocker compose exec backend python manage.py status
Apply database upgradesdocker compose exec backend python manage.py migrate
Reset an officer's passworddocker compose exec backend python manage.py set-password <username>
Reset a lost authenticatordocker compose exec backend python manage.py reset-2fa <username>
Logsdocker compose logs -f backend
Backup the databasedocker compose exec -T db pg_dump -U evoting evoting > backup.sql
Upgradegit pull && docker compose up -d --build

Health check: GET /api/health. More in Operations guide and Troubleshooting.

Checklist before the election

  • HTTPS works; /api/health is healthy.
  • Strong secrets set; .env not in version control.
  • Two-step verification active for the Election Officer.
  • A test registration and test vote done on a separate test installation.
  • Database backup taken; booth hardware secured (BIOS password, ports).

Features

Everything a campus election needs

Built around how elections are really run: a desk, supervised booths and a results announcement.

🧭

Guided installation

A first-run wizard sets up the institution, logo, slip ID letters, the Election Officer (with mandatory two-step verification) and the first election. It locks itself when done.

SetupRegistrationReadyVotingClosedPublishedArchived
🪪

Desk registration

Unique Voter Slip IDs like SUE26-E1-483920 and single-use PINs, generated automatically.

🖥️

Supervised booths

A booth works only after a one-time token plus the officer's authenticator code. Remove it and it stops instantly.

✨

Animated voting

Big candidate cards with photos, one position at a time, review and confirm. Light and dark themes.

🏆

Projector reveal

Results stay hidden until published. Reveal winner by winner with confetti; draws are shown honestly.

📜

Readable audit log

Every important action in plain language — who, what, which booth — grouped by category and filterable.

🔗

Public results link

Create a shareable results page with one click and delete it whenever you want.

How it works

From install to results in four steps

One officer, a few desk staff, and voters who just type two numbers.

Install & prepare

Run the wizard, add programmes (CSV import), candidates with photos and Desk Officers.

Register students

Desk Officers register students and hand out the slip with a Voter Slip ID.

Vote on booths

Voters enter the slip number and a PIN at an approved booth and choose once per position.

Publish & reveal

Close voting, publish, present on the projector and share the public link.

Security

A secret ballot you can defend

Identity and choice live in separate tables with no key between them. The server decides everything; the browser is never trusted.

🔒

One voter, one vote

Ballot and "voted" mark are written in one transaction with a row lock.

🛡️

Booth-only voting

Hashed one-time booth tokens and officer TOTP; revocation is immediate.

🙈

Hidden results

Counts never reach a browser until the officer publishes them.

🔑

Strong staff accounts

bcrypt passwords, mandatory two-step verification for officers, instant sign-out on deactivation.

🚦

Abuse protection

Rate limits, PINs cancelled after five wrong tries, sanitised input, formula-safe exports.

FAQ

Questions

Can anyone vote from their phone?

No. Votes are accepted only from booths the Election Officer has approved, so every vote happens under supervision.

Can the admin see who I voted for?

No. The ballot is stored without any reference to the voter, and the audit log records only that a ballot was cast.

What if two people submit at the same moment?

A database row lock guarantees exactly one ballot per voter, verified on PostgreSQL.

Does it work on free hosting?

Yes, on Render and Supabase. A built-in self-ping keeps the API and database awake. For a real election a server you control is recommended.

What if the officer loses their authenticator?

The operator runs manage.py reset-2fa on the server and the officer sets it up again.

Ready to run your election?

Clone the repository, set three secrets and start. The wizard does the rest.
